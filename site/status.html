Partial, and saying so in the code

Each of these is documented as a limitation in the capabilities reference rather than left to be discovered.

Partial

for_each: parallel is accepted but sequential

Iterations still run one after another. CruxCtx is a single mutable trace recorder, so concurrent nested ctx.step() calls are not sound without a crux-runtime change. An older gap-analysis document still claims this gives bounded concurrency with max_concurrency: 8; the capabilities reference supersedes it.

Unusable

analysis::replay_dry_run invokes a command that does not exist

It shells out to crux replay, which is not a subcommand. There is replay-debug, and run --replay.

Subset

json::jq is a subset, not jq

No reduce, no foreach, no variable bindings, no construction literals, and no stream semantics.

Heuristic

Two cost heuristics are hard-coded

analysis::latency_profile uses twice the median, and tighten_budget triggers above 80 percent spend. Neither is configurable.

Unreachable

Plugin steps can never satisfy --strict

Only the output shape can be declared. Strict compilation also needs an input schema and a confidence capability, which the plugin protocol does not carry yet. This is exactly why the project's own showcase.crux emits twelve missing_contract warnings.

Documentation that has drifted

Worth knowing before you rely on any of these documents.

DocumentWhere it is wrong
CHANGELOG.md Stops at 0.1.0 from April 2026. The workspace is 0.4.0 with tags through v0.4.2. It has only an Unreleased and a 0.1.0 section, so it is not a release history.
CONFORMANCE.md Titled v0.3. Its StepKind MUST list is action, delegation, speculation, checkpoint, pipe, join, route, gate — the implemented enum is Plain, Delegation, Branch, Speculation. Its StepStatus MUST list is likewise not the built enum. It describes a design that was not built.

docs/crux-syntax-reference.md Omits StepOrigin entirely, and the metadata and findings fields on Step. The source has both.
docs/src/ An orphaned near-empty parallel tree. book.toml points at docs, and the live table of contents is docs/SUMMARY.md. Every crate page under docs/src/crates/ is a three-line stub.
docs/reports/crux-gap-analysis.md Partly superseded. Its P1, P2, and P3 items are now marked supported in the capabilities reference. Only the compound-budget and shell::capture P0s remain open.

Two open P0 bugs

Compound budgets silently drop a constraint

BudgetDef is an #[serde(untagged)] enum, so a compound limit like { calls: 40, duration_ms: 900000 } matches only one variant and the second constraint is discarded without an error. Source of the finding: a comparison of maestro_smoketest.crux against the schema, the standard library, and the agentic handlers.

shell::capture is in the wrong crate

It lives in crux-agentic rather than crux-stdlib, so a pipeline that only needs to capture a shell command still pulls in the whole agentic stack. Open, and flagged P0 in the gap analysis.

What CI does not cover

  • LLM-backed tests never run. The BAML handler crates are regenerated and clippy-checked, but the llm_extract and planner test binaries are excluded from the nextest run.
  • mdBook is not built in CI. A tracked TODO asks for it, alongside moving lint-crux into the remote workflow.
  • No credential-free feature matrix. Another tracked TODO, for the agentic and optional-feature paths.
