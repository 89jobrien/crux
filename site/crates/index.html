Eighteen members, one glob

The workspace declares members = ["crates/*", "xtask"]. Descriptions below are the description field from each crate's own manifest, not paraphrase.

0.4.0 MIT edition 2024 MSRV 1.89.0

Wire and domain

Leaf crates with no workspace dependencies. Everything else in the graph depends on these and never the reverse.

Leaf layer
CrateDescriptionOwns
crux-types Serializable wire-format types for the crux agentic DSL Budgets, emissions, errors, ids, planner types, recovery, steps, and tasks. Data only — no runtime, no async, no LLM.
crux-model Canonical model ID types and provider-specific parsers for crux Parsing OpenAI, Anthropic, and Ollama model strings into a canonical ModelId.
crux-derive Proc macros for the crux agentic DSL #[crux::agent], #[crux::harness], #[crux::evolve]. The directory is crux-macros; the package is crux-derive.
crux-schema Runtime-independent trace schema and combinators for Crux Crux<T> itself, plus trace combinators. Missing from the README crate table.
crux-domain Pure domain types for the crux agentic DSL — no async, no LLM deps Planning, action, and event vocabulary.

Runtime and interpretation

CrateDescriptionOwns
crux-runtime Core types, traits, and runtime for the crux agentic DSL CruxCtx, the Agent trait, replay, hooks, governance, registry, trust, safety, and approval. The busiest crate by test count: 80 tests in ctx.rs alone, then replay 26, registry 20, speculation 14, governance 13, trust 12.
crux-script YAML-driven pipeline scripting for the crux agentic DSL The .crux schema, validation, expression evaluation, the step runner, and HandlerRegistry.

Handlers and adapters

CrateDescriptionOwns
crux-stdlib Standard library handlers for crux-script pipelines (fs, git, json, text, ctrl) Deterministic handlers only. No LLM, no network.
crux-baml BAML-powered LLM handlers for crux-script pipelines (analyze, confidence, complete, extract, decompose, plan) Thin wrappers over the generated BAML client. The generated baml_client/ is gitignored and stubbed in CI.
crux-plugin Subprocess plugin host for crux pipelines Newline-delimited JSON over stdin and stdout: Declare, Invoke, Shutdown.
crux-task Project task management for crux Ships a second binary, crux-task. Backends: redb by default, or sqlite behind a feature.

The standard library does not hold shell::capture. It lives in crux-agentic, which forces the full agentic stack onto simple operations pipelines. The gap analysis flags this as a P0 and it is still open.

Orchestration

CrateDescriptionOwns
crux-agentic Built-in step handlers for crux-script pipelines LLM, container, analysis, CI, review, triage, and SQLite handlers. Optional docker feature via bollard. The widest internal dependency fan-in of the handler crates.
crux-planner Goal-to-pipeline planner for crux-script Two subsystems: pipeline planning across deterministic, rule, and LLM strategies, plus harness evolution.
crux-improve Improvement protocol types for the crux agent runtime Strategies, diffs, comparisons, and policies over trace types. A single-file crate.
crux-regression Golden trace regression storage and evaluation for Crux A content-addressed golden trace store with baseline promotion and offline evaluation. Its manifest forbids depending on the runtime, the script interpreter, the agentic stack, or the CLI.

Interfaces

CrateDescriptionOwns
crux An agentic DSL for Rust — inspectable, serializable, replayable agent execution The facade. Re-exports the domain, the derive macros, the runtime, and optionally the script crate. Also holds the 13 integration test files.
crux-cli Command-line interface for crux pipelines Builds the crux binary. Depends on nine internal crates — the widest fan-in in the workspace.
xtask no description field publish = false. Depends only on ureq and serde_json. A publishing helper.

Naming traps

Three things that trip up a first reading of the tree.

  • The directory is crux-macros and the package is crux-derive.
  • The facade package is crux, not cruxx. The older cruxx-* names survive in docs/superpowers/, which is historical.
  • The crux name on crates.io is owned by a different publisher. Install from git with an explicit tag, as shown on the CLI page.
