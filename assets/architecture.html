Layers

Nothing in an inner layer knows about an outer one. crux-types has no workspace dependencies at all, and crux-regression is deliberately forbidden from reaching back into the runtime, the script interpreter, the handler stack, or the CLI.

Ports and adapters

Four traits carry the boundaries. The rest of the runtime is concrete.

Port traits and the adapters that satisfy them
PortAdaptersPurpose
RegistryBackend InMemoryBackend (default), RedbBackend (feature redb) Persistence port for the task registry, with compare-and-swap on write.
SafetyPolicy evolve strategies validate(diff, base) and requires_approval(diff) over harness evolution.
ApprovalGate terminal approval adapter, in crux-agentic Requests human sign-off before an accepted change lands.
Context mirrors CruxCtx Step, hook, budget, and streaming operations behind an abstraction, for injecting mocks. Agent is not generic over it — Agent::run takes &mut CruxCtx directly.

GovernancePolicy is a serializable struct, not a trait. And the runtime has no AutoApproveGate type; only the terminal approval adapter exists, in crux-agentic. Older changelog and agent-guide entries still mention an AutoApproveGate that was never built.

What is inside CruxCtx

The runtime context is the thing a step records into, and the reason concurrent nested steps are not sound today: it is one mutable recorder.

  1. Step recording

    A step recorder that appends each Step as it completes, with stable id, kind, status, origin, timings, and input and content hashes.

  2. Replay cache

    The recorded snapshot store that --replay reads from, matched by name plus ordinal hash. Strict mode fails on mismatch; lenient mode does a forward name scan, so ordinal shifts are the designed recovery path rather than a fallback.

  3. Budget tracking

    A tracker enforcing the four independently measured limits — handler attempts, model tokens, wall-clock milliseconds, and dollars. Delegated budgets are enforced in the child context.

  4. Hooks, governance, trust, and child traces

    Hook dispatch around step boundaries, the governance policy check, trust scoring, and the tree of child Crux values produced by delegation.

Drift tracking

Thirteen hash-tracked protocol surfaces are declared in taskit.toml and checked by taskit check-protocol-drift in CI, so an intentional change to a public trait has to be acknowledged rather than slipped in.

Tracked surfaces include crux-domain-planner, crux-runtime-recorder, crux-runtime-audit, crux-runtime-safety, crux-runtime-agent, crux-runtime-approval, crux-runtime-context, crux-types-emission, crux-script-step_runner, crux-agentic-provider, crux-plugin-discovery, crux-improve-lib, and crux-planner-generator.

The crate list in taskit.toml omits crux-cli, crux-macros, crux-schema, crux-regression, and crux-task, so affected-crate propagation for those members is behind the actual workspace.
