Check before you run

check resolves every handler and reports a missing_contract warning for any handler whose input schema or confidence capability is not fully declared. Diagnostics go to stderr, wrapped in ANSI.

crux check examples/showcase.crux
$ crux check examples/showcase.crux
warning[missing_contract]: examples/showcase.crux [steps[0].arms[0]]: handler 'shell::capture' has no complete contract
warning[missing_contract]: examples/showcase.crux [steps[1]]: handler 'ctrl::log' has no complete contract
...
warning[missing_contract]: examples/showcase.crux [steps[6]]: handler 'ctrl::log' has no complete contract

Summary: 1 file(s) checked, 0 error(s), 12 warning(s)

Even the project's own flagship example produces twelve warnings. That is the contract system being stricter than 1.0, not a broken example.

Run a pipeline

--dry-run and --check resolve handlers without executing them and write no trace, which makes them safe as a first move on an unfamiliar pipeline.

crux run --dry-run
$ crux run examples/showcase.crux \
      examples/input_showcase.json --dry-run
Pipeline: showcase (7 steps)

   1. ctrl::assert
   2. ctrl::log

Replay

Replay re-runs a pipeline seeded by a recorded snapshot. Steps are matched by name plus an ordinal hash. Strict mode fails on mismatch; lenient mode does a forward name scan, so an ordinal shift is the designed recovery path rather than a fallback.

just replay-demo
$ crux run examples/showcase.crux \
      examples/input_showcase.json \
      --replay examples/fixtures/showcase_trace.json \
      --replay-mode lenient

Both the pipeline, its input, and a committed trace fixture live in the repository, so this demo runs as checked in. just replay-demo wires up all four replay variants.

Plan a pipeline from a goal

The default rule planner needs no API key and makes no network call. It emits a skeleton; handlers that are not built in must be registered through a plugin, or replaced, before running with --strict.

crux plan
$ crux plan --goal "summarize the latest release notes"
pipeline: "summarize-the-latest-release"
steps:
  - step: llm::complete
    handler: llm::complete

llm::complete is a planner template, not one of the 64 catalogued handlers. Treat the output as a starting shape to complete rather than a runnable pipeline.
