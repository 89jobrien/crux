The return value

Observability travels with the result

A tracing span tells you something happened and how long it took. Crux returns a value that carries the steps, the delegations, and the timing inside the type the caller already has to handle.

Crux<T> = Result<T, CruxErr> + steps + child runs + run metadata

Written in the project's own words:

This is the most significant departure from tracing / OpenTelemetry. Those libraries treat a span as a timing primitive — it happened, here is how long it took. crux:: treats a step as an epistemic primitive: it happened, here is how sure we are the output is correct.

docs/walkthrough/02-core-types.md

Two consequences follow. You cannot forget the trace, because returning Crux<T> returns the trace with it. And replay is trivial, because the trace is the return value — a snapshot of it seeds the next run.

A real trace

Steps laid out by duration, tagged by origin

Every step records a StepOrigin: Live or Replayed. The CLI already prints that as [LIVE] and [CACHED / REPLAYED] beside every row; this is the same reading, drawn to scale.

Two surfaces

YAML pipelines and typed Rust agents, one trace

Write declarative .crux files for workflows, or #[crux::agent] when you need typed logic, delegation, and confidence routing. Both produce the same Crux<T>.

Pipeline

.crux files

Four parts: pipeline:, an optional budget: measured independently as steps, tokens, wall-clock milliseconds, and dollars, an optional display:, and an ordered steps: list. 28 example pipelines ship in the repo.

Rust API

#[crux::agent]

Implement Agent::run(ctx, input) -> Result<Crux<Self::Output>, CruxErr> and get the same typed trace back. Combinators cover pipe, join, speculate, route-on-confidence, and delegate.

Where it stands

A tested core, a pre-1.0 CLI, and honest gaps

Crux is a mature library with a young command line. The distinction matters, so the status page says exactly which is which rather than averaging them into one number.

Shipped

Pipeline execution

64 documented handlers, all four loop primitives, typed budgets, strict and lenient replay, a task registry with compare-and-swap, and a subprocess plugin host. 1,135 #[test] attributes across the workspace.

Partial

for_each: parallel

Accepted, but still executes iterations sequentially. CruxCtx is a single mutable trace recorder, so concurrent nested ctx.step() calls are not sound without a runtime change.

Not wired

Advanced CLI subcommands

regress, handlers, doctor, init, trace, and schema exist in source and are absent from the published install, which predates them.
